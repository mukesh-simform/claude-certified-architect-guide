Scenario 1 · Customer Support Resolution Agent

17 questions

An Agent SDK support agent with MCP tools get_customer, lookup_order, process_refund and escalate_to_human, targeting 80%+ first-contact resolution.

Q1D2 · Tool Design & MCP

In testing, the agent frequently calls get_customer when users ask about order status, even though lookup_order would be more appropriate. What should you examine first to address this issue?

Show answer
Correct answer: C
Tool descriptions are the main signal Claude uses to choose a tool, and vague or overlapping descriptions are the most common cause of misselection. Check them first, before adding classifiers, removing tools or writing large sets of examples.
Q2D2 · Tool Design & MCP

Your get_customer tool returns all matches when searching by name. When there are several, Claude picks the customer with the most recent order, and production data shows 15% of multi-match cases then proceed with the wrong account. How should you address this?

Show answer
Correct answer: D
When a lookup returns several customers, the agent must ask for an additional identifier and must not pick one by heuristic. Confidence thresholds, returning only the "most likely" match and inferring from context are all heuristics, and any of them can act on the wrong customer's account.
Q3D2 · Tool Design & MCP

Production logs show that when customers include "account" in their message (e.g., "check my account for the order"), the agent calls get_customer first 78% of the time. Without "account" (e.g., "check on the order I placed"), it calls lookup_order first 93% of the time. The tool descriptions are well written. What is the most likely root cause?

Show answer
Correct answer: A
When the descriptions are already good and the behaviour flips on a single keyword, look for system prompt wording such as "always verify the customer's account first" that steers selection. Blaming base training or reaching for fine-tuning skips the cheap, likely fix, and more description text doesn't address a prompt-level bias.
Q4D1 · Agentic Architecture

Production data shows that in 12% of cases, your agent skips get_customer entirely and calls lookup_order using only the customer's stated name, occasionally leading to misidentified accounts and incorrect refunds. What change would most effectively address this reliability issue?

Show answer
Correct answer: D
Identity verification before financial operations is a hard rule, so it needs deterministic enforcement. A programmatic prerequisite guarantees the order; prompt wording and few-shot examples only make compliance more likely, which isn't enough when a miss means a refund on the wrong account. A routing classifier controls which tools are available, not the order they are called in.
Q5D2 · Tool Design & MCP

Production metrics show your agent averages 4+ API round-trips per resolution. Analysis reveals Claude often requests get_customer and lookup_order in separate sequential turns, even though both lookups are independent and needed up front. What's the most effective way to reduce round-trips?

Show answer
Correct answer: B
Claude can request several independent tools in one response. Ask for this in the prompt, and make the harness run them and return all the results in a single user message, because splitting results across messages teaches the model to stop calling tools in parallel. Speculative calls waste work and context. A generic multi-mode tool blurs the descriptions Claude relies on for selection. max_tokens has nothing to do with it.
Q6D1 · Agentic Architecture

Production logs reveal the agent misinterprets data: Unix timestamps from get_customer, ISO 8601 dates from lookup_order, and numeric status codes (1=pending, 2=shipped). Some tools are third-party MCP servers you cannot modify. What's the most maintainable approach to normalize data formats?

Show answer
Correct answer: C
A PostToolUse hook is deterministic: it transforms results in one place before Claude reads them, whether the server is yours or a third party's. Prompt documentation and an extra normalization tool both depend on the model remembering to apply them, and you can't rely on vendors changing their servers.
Q7D5 · Context Management

Your agent achieves 55% first-contact resolution, well below the 80% target. Logs show it escalates straightforward cases (standard damage replacements with photo evidence) while attempting to autonomously handle complex situations requiring policy exceptions. What's the most effective way to improve escalation calibration?

Show answer
Correct answer: A
The agent doesn't know where the decision boundary is, so state it: explicit, policy-based criteria plus examples on both sides. Sentiment doesn't track case complexity, self-reported confidence is poorly calibrated (the agent is already confidently wrong on hard cases), and a separate classifier is heavy infrastructure before the prompt has even been fixed.
Q8D5 · Context Management

Your support agent uses progressive summarization: when context reaches 70% capacity, older turns are summarized while recent ones stay verbatim. Customers reference specific amounts stated 20+ turns ago (e.g., "the 15% discount I mentioned"), but the agent responds with incorrect values because these details were condensed into vague summaries like "discussed promotional pricing." What's the most effective fix?

Show answer
Correct answer: B
Summaries lose exact values, so values the agent must act on shouldn't live in the summary at all. A persistent case-facts block that travels with every prompt keeps amounts, dates and order numbers exact however much the narrative is compressed. Retrieval triggered by phrases is brittle, a better summary prompt still risks loss, and a later trigger only delays the problem.
Q9D1 · Agentic Architecture

Simple requests like "refund order #1234" succeed in 3-4 tool calls with a 91% resolution rate. Complex requests like "I've been charged twice, my discount didn't apply, and I want to cancel" average 12+ tool calls with only 54% resolution: the agent investigates concerns one after another and gathers redundant customer data for each. What's the most effective change?

Show answer
Correct answer: C
Splitting the request into independent concerns and investigating them in parallel, with the customer context fetched once and shared, removes both the redundant lookups and the slow sequential handling. Consolidating tools blurs their purpose, checkpoints make the process more sequential, and examples don't remove the duplicated data gathering.
Q10D1 · Agentic Architecture

You're implementing the agentic loop for your support agent. After each API call to Claude, you need to decide whether to continue (execute the requested tools and call Claude again) or stop (present the final response to the customer). What determines this decision?

Show answer
Correct answer: D
stop_reason is the authoritative signal: "tool_use" means Claude wants tools run, and "end_turn" means it has finished. Text patterns are fragile, a response can contain text and tool calls together, and an iteration cap is a safety limit, not a completion signal.
Q11D4 · Prompt Engineering

Your agent handles single-concern requests with 94% accuracy, but multi-concern messages (e.g., "I need a refund for order #1234 and also want to update my shipping address for order #5678") drop to 58%: it addresses only one concern or mixes up parameters between orders. The platform team can't add new services this quarter, so the fix has to be made in the agent's prompt. What's the most effective change?

Show answer
Correct answer: A
Within a prompt-only constraint, examples that show how to split the concerns, which tool handles each, and how to keep order #1234's parameters apart from order #5678's teach the exact behaviour that's failing. A one-line instruction is the kind of prose that is already being followed inconsistently. Merging tools isn't a prompt change and hurts selection, and asking customers to restructure their messages pushes the problem onto them.
Q12D2 · Tool Design & MCP

The lookup_order MCP tool returns the text "Operation failed" for every problem: order-service timeouts, malformed order IDs, and orders belonging to another account. The agent either retries everything or gives the customer a vague apology. What change best lets the agent choose the right recovery?

Show answer
Correct answer: B
The agent can only recover sensibly if it knows what kind of failure happened. A timeout is worth retrying, a malformed ID needs a corrected input or a clarifying question, and a permission problem should never be retried. A generic message after many retries hides that, a blanket retry rule treats every error the same, and an empty result hides the failure completely.
Q13D4 · Prompt Engineering

Complex cases (billing disputes, multi-order returns) score 15% lower on customer satisfaction than simple cases, even when the resolution is technically correct. Root-cause analysis shows the agent's resolutions are accurate but its explanations are inconsistent: they sometimes omit relevant policy details, timelines, or next steps. You want to improve quality without adding human review. What's most effective?

Show answer
Correct answer: C
The agent hasn't been shown what a complete explanation looks like. Few-shot examples covering policy, timeline and next steps set that pattern consistently. Self-critique in the same session shares the blind spots that caused the omissions, a bigger model doesn't fix an unspecified output pattern, and a confirmation question hands quality control to the customer.
Q14D2 · Tool Design & MCP

After calling get_customer and lookup_order, the agent has all available system data but still faces uncertainty. Which situation is the most appropriate trigger for calling escalate_to_human?

Show answer
Correct answer: D
When policy is silent on the customer's specific request, the agent has no authority to decide, so it should escalate. The other cases are within the agent's data and policy: a covered cancellation, two concerns it can handle in turn, and a delivery dispute it can investigate and explain first.
Q15D4 · Prompt Engineering

Production logs show the agent sometimes selects get_customer when lookup_order would be more appropriate for ambiguous requests like "I need help with my recent purchase." You decide to add few-shot examples. Which approach will most effectively address this issue?

Show answer
Correct answer: A
The failures are on ambiguous requests, so the examples should sit on that decision boundary and show why one tool beats the plausible alternative. Clear-cut examples don't teach the hard cases, grouping by tool doesn't show the contrast, and dropping the reasoning removes what generalizes.
Q16D1 · Agentic Architecture

Policy says refunds above $500 need human approval. The system prompt states this rule clearly, yet logs show the agent occasionally calls process_refund for amounts between $600 and $900. Which change guarantees the policy is followed?

Show answer
Correct answer: B
Only interception outside the model guarantees compliance. A PreToolUse hook sees every process_refund call and denies it deterministically. Stronger wording and more examples still leave a non-zero failure rate, and a weekly audit catches violations after the money has gone.
Q17D5 · Context Management

lookup_order returns about 40 fields per order (warehouse IDs, carrier codes, internal flags). In long sessions covering several orders, the context fills with order data and the agent starts losing track of what the customer said earlier. What's the most effective fix?

Show answer
Correct answer: C
Verbose tool output takes up context out of proportion to its value. Trim it at the source, before it enters the history. A bigger window postpones the problem, blanket summarization loses exact details the customer referred to, and splitting chats makes the customer do the work.

Scenario 2 · Code Generation with Claude Code

11 questions

A team using Claude Code day to day: slash commands and skills, CLAUDE.md configuration, plan mode versus direct execution.

Q18D3 · Claude Code Config

Claude follows your API conventions inconsistently in packages/api. The conventions live in .claude/rules/api-conventions.md and are pulled into packages/api/CLAUDE.md with an @ import. Before changing anything, what's the best first diagnostic step?

Show answer
Correct answer: D
/memory shows which memory files Claude Code has loaded, so you can see whether the import or rules file is being picked up at all. Duplicating the content hides the real fault, Claude Code doesn't keep a stale CLAUDE.md cache to clear, and asking for a recap tests recall, not configuration.
Q19D2 · Tool Design & MCP

Your team wants to add a GitHub MCP server to enable PR lookups and CI status checks through Claude Code. Each of the six developers has their own GitHub personal access token. You want consistent tooling across the team without committing credentials to version control. What's the most effective configuration approach?

Show answer
Correct answer: D
A project-scoped .mcp.json gives everyone the same server definition, and ${GITHUB_TOKEN} is expanded from each developer's own environment at runtime, so no secret is committed. A committed .env leaks tokens, per-user setup drifts, and placeholder-plus-override duplicates the config on every machine.
Q20D3 · Claude Code Config

Your team's /migration skill has three production issues: (1) developers invoke it without arguments, producing poorly named files; (2) the skill picks up schema details from unrelated earlier conversation; (3) a developer accidentally ran a destructive cleanup because the skill pre-approved broad tool access. Which configuration addresses all three issues?

Show answer
Correct answer: B
argument-hint is only an autocomplete hint and doesn't force input, so pair it with an instruction to ask for a migration name when none is given. context: fork runs the skill in an isolated sub-agent, so earlier conversation can't leak in. allowed-tools pre-approves the tools it lists rather than restricting Claude to them, so a broad list let the destructive command run without a prompt. Narrow it to the file tools the skill needs and anything else goes back to a normal permission prompt; use deny rules in settings for a hard block. Prose instructions can't remove context that is already loaded.
Q21D3 · Claude Code Config

Developers report that after running your /explore-alternatives skill, Claude's later responses are influenced by the exploration, sometimes referencing abandoned approaches or keeping exploratory context that confuses the actual implementation work. What's the most effective way to configure this skill?

Show answer
Correct answer: A
context: fork runs the skill in a separate sub-agent context and returns only its result, so the abandoned approaches never enter the main conversation. Start/end markers don't remove anything from context, scope changes who can use the skill rather than where it runs, and ! runs shell commands, not reasoning.
Q22D3 · Claude Code Config

Your team's CLAUDE.md has grown to over 500 lines, mixing TypeScript conventions, testing guidelines, API patterns and deployment procedures. Developers find it hard to locate and update the relevant sections. What does Claude Code support for organizing project-level instructions into focused, topic-specific modules?

Show answer
Correct answer: C
.claude/rules/ is the supported way to split a monolithic CLAUDE.md into topic files, optionally scoped with glob patterns. READMEs aren't loaded as instructions, config.yaml section maps don't exist, and nested CLAUDE.md files add to the parent's instructions rather than replacing them.
Q23D5 · Context Management

Q24D3 · Claude Code Config

Including 2-3 full exemplar endpoint implementations as context significantly improves consistency when generating new API endpoints. However, this context is only useful for creating new endpoints, not for bug fixes, code reviews or other work in the API directory. What's the most efficient configuration?

A skill loads the heavy exemplar context only when someone is actually creating an endpoint. CLAUDE.md would load it in every session, path-scoped rules would load it for every task in the API directory, and pasting it by hand is error-prone and inconsistent.
Q25D3 · Claude Code Config

You've asked Claude Code to implement a function that transforms API responses into a normalized internal format. After two iterations the output structure still doesn't match: some fields are nested differently and timestamps aren't formatted correctly. Q26D3 · Claude Code Config

You've created a /commit skill in .claude/skills/commit/SKILL.md that your team uses. One developer wants to customize it for their personal workflow (different commit message format, additional checks) without affecting teammates. What should you recommend?

Q27D3 · Claude Code Config

Three developers have used Claude Code for months, and Claude correctly follows the "always include comprehensive error handling" guideline for them. Claude Code doesn't learn per-user preferences or cache old copies, and version drift wouldn't produce this pattern.
Q28D1 · Agentic Architecture

Your team uses Claude Code to generate code changes, but subtle issues (performance optimizations that break edge cases, cleanups that change behaviour) only surface when another team member reviews the PR. Claude's generation reasoning shows it considered these cases but concluded its approach was correct. Which approach directly addresses the root cause of this self-review limitation?

Show answer
Correct answer: A
A model reviewing its own work is anchored by its own reasoning. It already considered these cases and talked itself into them. An independent instance that never sees that reasoning catches what the generator rationalized away, just as human review catches what the author misses. More self-critique or deliberation in the same context repeats the same blind spots.

Scenario 3 · Multi-Agent Research System

13 questions

A coordinator delegating to web search, document analysis and synthesis subagents that together produce cited research reports.

Q29D1 · Agentic Architecture

The document analysis agent finds that two credible sources directly conflict: a government report states 40% growth while an industry analysis states 12%. Both appear legitimate, and the discrepancy could significantly change the research conclusions. What's the most effective way for the document analysis agent to handle this?

Show answer
Correct answer: B
The subagent should finish its work, keep both values with their sources, and flag the conflict explicitly so the coordinator can decide. Passing both values on unflagged loses the signal, halting mid-task wastes the rest of the analysis, and choosing one value makes a decision that belongs to the coordinator.
Q30D1 · Agentic Architecture

The document analysis subagent often hits failures: corrupted PDF sections, password-protected files and parsing timeouts. Currently any exception immediately terminates the subagent and returns an error to the coordinator, so the coordinator is constantly involved in routine error handling. What's the most effective architectural improvement?

Show answer
Correct answer: C
Handle errors at the lowest level that can resolve them. The subagent retries timeouts itself, and only what it can't fix goes up, with what was attempted and what was recovered. Marking failures as success hides them, a separate error agent adds coordination overhead, and pre-validation can't predict parsing failures.
Q31D1 · Agentic Architecture

During a materials research task, the web search subagent queries three source categories: academic databases return 15 relevant papers, industry reports return "0 results found," and patent databases return "Connection timeout." When designing error propagation to the coordinator, what approach enables the best recovery decisions?

Show answer
Correct answer: D
A timeout means the query never ran and might succeed on retry. "0 results" means it ran and found nothing. If these are reported the same way, as failures, as a retry list or as a single percentage, the coordinator will retry queries that already succeeded and miss the one that really failed.
Q32D1 · Agentic Architecture

Web search covered 3 of 5 requested source categories (competitor websites and industry reports succeeded; news archives and social media feeds timed out). Document analysis succeeded for every provided document. The synthesis agent must now produce a findings summary from this mixed-quality input. What's the most effective error propagation strategy?

Show answer
Correct answer: A
Coverage annotations deliver value from the data you have while telling the reader exactly where the gaps are. Silently omitting the gaps misleads readers, and blocking or failing the whole task discards good work over sources that may stay unavailable.
Q33D1 · Agentic Architecture

When researching a broad topic, both the web search agent and the document analysis agent investigate the same subtopics, producing significant overlap in findings. Token usage has nearly doubled without a matching increase in research coverage. What's the most effective way to address this?

Show answer
Correct answer: B
Overlap is a delegation problem, so fix it at delegation time with distinct, non-overlapping assignments. Deduplicating afterwards still pays for the redundant work, sequential execution gives up parallelism, and a shared scratchpad introduces races and coordination the agents weren't designed for.
Q34D2 · Tool Design & MCP

Production logs show requests to "analyze the quarterly report I uploaded" are routed to the web search agent 45% of the time instead of the document analysis agent. The web search agent has an analyze_content tool described as "analyzes content and extracts key information," while the document analysis agent has analyze_document described as "analyzes documents and extracts key information." How should you address this misrouting?

Show answer
Correct answer: D
The two tools are nearly identical in name and description, so the overlap is at the naming level. Renaming the vague tool and stating its scope removes the ambiguity at its source. Expanding only the other tool leaves the overlap in place, while examples and classifiers work around unclear tool definitions instead of fixing them.
Q35D1 · Agentic Architecture

During testing, the synthesis agent often needs to verify specific claims while combining findings. Currently it returns control to the coordinator, which invokes the web search agent and then re-invokes synthesis, adding 2-3 round-trips per task and increasing latency by 40%. 85% of verifications are simple fact-checks; 15% need deeper investigation. What's the most effective approach?

Show answer
Correct answer: C
A narrowly scoped tool covers the common 85% locally and leaves complex checks on the existing coordinated path. That is least privilege. Batching at the end blocks synthesis steps that depend on verified facts, full web search access over-provisions the synthesis agent, and speculative caching can't predict what will need checking.
Q36D5 · Context Management

Final reports contain statistics that reviewers can't trace. Subagents return prose summaries such as "several industry reports suggest adoption tripled," and the synthesis agent can no longer tell which source said what, or when. What's the most effective fix?

Show answer
Correct answer: A
Once a subagent summarizes into prose, the link between claim and source is gone for good, and nothing downstream can rebuild it. Capture structured claim–source mappings, with publication dates, at the point of extraction. Citations assigned afterwards from a source list or a web search are guesses, and longer prose is still prose.
Q37D5 · Context Management

Production monitoring reveals inconsistent synthesis quality. When aggregated results total ~75K tokens, the synthesis agent reliably cites information from the first 15K and final 10K tokens but often omits critical findings in the middle 50K, even when those findings directly address the research question. How should you restructure the aggregated input?

Show answer
Correct answer: B
This is the "lost in the middle" effect: models attend best to the start and end of long inputs. Putting a key-findings summary first places the critical content where attention is strongest, and section headers make the body easy to navigate. Heavy summarization throws detail away, and reordering or rotating only changes which findings get lost.
Q38D2 · Tool Design & MCP

You gave the document analysis agent a general-purpose fetch_url tool so it could load documents from URLs. Production logs reveal it now often fetches search engine result pages to run ad-hoc web searches, behaviour that should go through the web search agent. What's the most effective fix?

Correct answer: C
A purpose-built load_document tool makes the misuse structurally impossible while keeping the capability the agent needs. Domain blocklists are whack-a-mole, routing every document through the web search agent breaks role boundaries in the other direction, and prompt instructions are probabilistic.
Q39D5 · Context Management

Combined outputs from the web search agent (~85K tokens) and the document analysis agent (~70K tokens) total 155K tokens, but the synthesis agent performs best with inputs under 50K tokens. What's the most effective solution?

Show answer
Correct answer: D
The volume is generated unnecessarily upstream. Design the upstream output format around the downstream budget: key facts, citations and scores, not transcripts and reasoning chains. An extra summarization agent, batching or retrieval all process bloat that shouldn't have been produced, and each adds latency and failure points.
Q40D1 · Agentic Architecture

The coordinator gathers the user's constraints during the conversation (only 2022–2024 data; exclude vendor-funded studies), then spawns the document analysis subagent with the prompt "Analyze the uploaded documents for relevant findings." The subagent's output includes 2019 figures and vendor-funded studies. What's the root-cause fix?

Show answer
Correct answer: A
Subagents start with only what their prompt gives them. They never saw the user's constraints, so the coordinator must pass them explicitly. A bigger window doesn't add context that was never sent, a downstream filter treats the symptom after the work is wasted, and a history-query tool reinvents the prompt as a fragile side channel.
Q41D1 · Agentic Architecture

The coordinator delegates three independent subtopics to search subagents, but logs show it spawns one, waits for its result, then spawns the next, so total latency is the sum of all three. What change lets the subagents run in parallel?

Agents and Claude Code sessions that explore and explain a large codebase using the built-in tools plus MCP servers.

Engineers use an agent built on Claude's built-in tools to answer questions about a 2,000-file monorepo. Q44D1 · Agentic Architecture

You're building an internal code Q&A agent with the Claude Agent SDK. It must explore code but never modify files or run shell commands. Occasionally, when a user says "go ahead and fix that typo," it edits a file. What's the most reliable fix?

Show answer
Correct answer: A
If the agent must never write, don't give it write tools. Restricting the tool list is deterministic least privilege. Prompt rules and examples are probabilistic, and a PostToolUse log only records the edit after it has already happened.
Q45D1 · Agentic Architecture

Yesterday you spent an hour with Claude Code mapping the billing module. Overnight a teammate's merge rewrote 22 of the 30 files you analyzed. You want to continue today. What's the best way to pick up the work?

Show answer
Correct answer: B
With most of the analyzed files rewritten, the old tool results in a resumed session are stale and will mislead the analysis. Start fresh, carry the conclusions forward as an injected summary, and point Claude at the changed files. Compacting or forking keeps the stale state as the baseline.
Q46D5 · Context Management

Two hours into mapping a legacy auth system, Claude starts describing "typical patterns" instead of the specific classes it found earlier and contradicts some of its earlier findings. You need several more hours of investigation. What's the most effective approach?

Show answer
Correct answer: C
Generic answers and contradictions are signs of context degradation. A scratchpad file acts as external memory that survives compaction or a fresh session, so the specifics stay exact. Re-reading everything refills the context, a bigger window only delays degradation, and a compressed summary on its own is where those specifics get lost.

Scenario 5 · Claude Code for Continuous Integration

11 questions

Claude Code running in CI/CD for automated code review and test generation, where false positives erode trust.

Q47D4 · Prompt Engineering

The code review component works iteratively: Claude analyzes a changed file, then may request related files via tool calls to understand context before giving final feedback. You're evaluating the Message Batches API to reduce costs. What is the primary technical constraint when considering batch processing for this workflow?

Show answer
Correct answer: D
Each batch request is a single, asynchronous request and response. You can't execute a requested tool and feed the result back within it, so a multi-turn tool loop doesn't fit. Batches do accept tool definitions and do correlate results via custom_id. Latency matters too, but it isn't the constraint that breaks this workflow.
Q48D4 · Prompt Engineering

Your CI/CD system performs three types of analysis: (1) quick style checks on each PR that block merging, (2) comprehensive security audits run weekly, and (3) test case generation triggered nightly. The Message Batches API offers 50% cost savings but can take up to 24 hours. Which combination correctly matches each task to its API approach?

Show answer
Correct answer: A
Blocking work that developers wait on needs synchronous calls. Scheduled background jobs, such as weekly audits and nightly generation, can tolerate batch latency and take the 50% saving.
Q49D3 · Claude Code Config

A CI job runs claude -p to write tests and then run them. The tests get written, but the run step never happens: the output says permission to use Bash for npm test was not granted. What's the best fix?

Show answer
Correct answer: B
Non-interactive runs can't answer permission prompts, so pre-approve exactly the commands the job needs with an allow rule. CLAUDE.md is guidance, not a permission system. CLAUDE_HEADLESS isn't a real setting. Skipping all permissions removes every guardrail and is only appropriate in an isolated sandbox, not on a shared runner.
Q50D4 · Prompt Engineering

Your automated review analyzes comments and docstrings. The current prompt tells Claude to "check that comments are accurate and up-to-date." Findings often flag acceptable patterns (TODO markers, straightforward descriptions) while missing comments that describe behaviour the code no longer implements. What change addresses the root cause?

Show answer
Correct answer: C
"Accurate and up-to-date" is vague, so the model fills the gap with its own interpretation. Explicit criteria define exactly what counts as a finding. Blame data, pre-filtering and examples work around the vague instruction instead of replacing it.
Q51D4 · Prompt Engineering

Your automated review generates test case suggestions for each PR. Claude suggests 10 test cases, but 6 duplicate scenarios already covered by the existing test suite. What change would most effectively reduce duplicate suggestions?

Show answer
Correct answer: D
Claude can't avoid duplicating tests it can't see. Putting the existing tests in context removes the cause. Narrowing the focus, asking for fewer suggestions or keyword filtering all guess around missing information.
Q52D3 · Claude Code Config

Your CI pipeline runs the Claude Code CLI with -p for code reviews. Developers like the reviews, but the narrative output is hard to integrate: they need structured data with file path, line number, severity and suggested fix to auto-post inline PR comments. What's the most effective approach?

Correct answer: B
The CLI's JSON output with a JSON schema gives machine-parseable, schema-conforming findings, which is a deterministic contract for the posting script. Scenario 6 · Structured Data Extraction

5 questions

A pipeline that extracts structured fields from invoices and contracts using JSON schemas, validation and human review.

Q58D4 · Prompt Engineering

An invoice pipeline asks Claude to "respond only with JSON." About 3% of responses fail to parse: trailing commas, missing brackets, or a sentence before the JSON. What's the most reliable fix?

Show answer
Correct answer: B
Schema-constrained output, whether through tool_use with an input_schema or native structured outputs, removes syntax errors entirely. Louder instructions and temperature 0 only make them rarer, and lenient parsing guesses at malformed output. Schema validity still doesn't guarantee correct values, so keep semantic validation.
Q59D4 · Prompt Engineering

Your extraction schema marks payment_terms as a required string. Many contracts have no payment terms at all, and reviewers find invented values like "Net 30" in about 20% of those contracts. What's the best fix?

Show answer
Correct answer: C
A required non-null field forces the model to produce something, so it fabricates. Making the field nullable lets it report absence honestly. An instruction conflicts with the schema, filtering one value misses other inventions and drops real "Net 30" terms, and retries can't find information that isn't in the document.
Q60D4 · Prompt Engineering

Semantic validation shows line items don't add up to the stated total in 6% of extractions. Failures are retried by re-sending the identical prompt, which rarely helps. Some failures come from invoices whose second page was never uploaded. What's the best approach?

Show answer
Correct answer: A
Retries help when the model can see what went wrong, so send back the document, the failed attempt and the specific validation errors. They can't help when the data is missing, as with the unuploaded page, so route those cases to a person. Identical retries repeat the mistake, schemas don't catch semantic errors, and a bigger model doesn't recover a missing page.
Q61D5 · Context Management

Extraction accuracy is 97% overall, so the team proposes ending human review. A breakdown by document type shows multi-currency invoices are only 61% accurate on the total field. What should you do?

Show answer
Correct answer: D
Aggregate accuracy hides segment failures. Calibrate field-level confidence against a labeled set, route low-confidence fields and weak segments to people, and keep sampling by document type and confidence band to catch drift. A flat 1% sample rarely sees the weak segment, uncalibrated self-reported scores are unreliable, and reviewing everything forever wastes the automation.
Q62D5 · Context Management

Reviewers checking extracted contract fields spend most of their time hunting through 40-page documents to find where each value came from. What change most speeds up review while improving trust in the output?

Show answer
Correct answer: B
Provenance at field level (page and excerpt) lets a reviewer verify each value in seconds, and confidence helps them prioritize. A summary adds more reading without linking values to evidence, hiding fields based on uncalibrated confidence risks missing errors, and same-session self-checks share the original blind spots.
